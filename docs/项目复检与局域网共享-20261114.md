## 已交付的改动

### 后台局域网访问

当前地址：**http://192.168.0.46:15173/login**。其他设备与电脑连接同一局域网后，可通过该地址使用自己的后台账号登录；本机地址 http://127.0.0.1:15173/login 也可使用。

- `scripts/lan-proxy.cjs` 增加 15173 转发，允许端口限定为本项目的 18080/15173，上游固定为 127.0.0.1 同端口。双向 TCP 转发支持 HTTP 和 WebSocket。
- `start-local.ps1` 新增受原 Windows Job 管理的 `LanFrontend` 服务，包含网卡选择、端口占用检测、就绪检查、状态记录和地址输出。一键启动会同时启动该入口；换网后以启动窗口新显示的 IP 为准。
- `/api`、`/uploads` 继续由 Vite 同源代理到当前副本后端，其他设备不会把 API 请求发向它们自己的 127.0.0.1。
- 当前 Windows 已有适用于实际 Node.js 程序的 TCP 入站允许规则，本轮没有修改全局防火墙或网络类别。其他设备实际连通性还取决于网络是否启用访客隔离、设备隔离等；本轮没有另一台物理设备的验收记录。

首次启动验证发现日志轮转函数的服务名白名单漏加 `LanFrontend`，已修正。失败后进程组自动回收、端口释放；保留 `startup-first.*.log`。随后真实启动成功，`last-start.json` 包含五个受管服务和 `LanFrontendUrl`。

### 医生详情双重跳转

旧代码在医生卡片的原生 `tap` 处理内又发送同名自定义 `tap`，页面使用 `bind:tap` 接收。离线事件序列和旧源码指纹对照复现一次点击产生两条 URL：

```text
/pages/schedule/detail?doctorId=7
/pages/schedule/detail?doctorId=undefined
```

第二个空详情成为栈顶并提示“参数错误”，返回一次露出第一个正常详情，与用户提供的真机现象吻合。

修复将自定义事件改为 `select`，首页和科室列表均改用 `bind:select`；缺失医生 ID 的事件不跳转，增加页面实例导航锁避免快速连点，导航失败和返回来源页时释放锁。

业务改动共五个文件，均位于 `wechat-miniprogram/miniprogram/`：

- `components/doctor-card/doctor-card.js`
- `pages/index/index.js`、`pages/index/index.wxml`
- `pages/schedule/list.js`、`pages/schedule/list.wxml`

定向 9 项通过，修复后客户端组合回归 63 项通过；独立上下文工程审查无阻断，并补充 7 项内存检查，覆盖导航失败后重试和详情接口收到正确 ID。事件派发仍为离线模拟，尚不能替代真机页面栈验收。需结束旧真机调试，重新编译、重新扫码加载新代码。
