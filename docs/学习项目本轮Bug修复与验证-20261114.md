# 学习项目本轮 Bug 修复与验证

日期：2026-11-14

本轮依据已核实的问题清单完成优先修复和低风险顺手修复，范围限定在当前副本 `D:/cxdownload/AIhealthcare`。原项目 `D:/cxdownload/Py/*` 未修改，未新增业务功能，也未改动真实业务库中的数据。

## 已处理内容

### 后端

- 排班新增、批量新增和修改会拒绝过去日期；批量排班会跳过今天已经过去的时段。
- `上午`、`下午` 与对应的标准时间字符串按同一时段处理，避免修改时被误判为身份变化。
- 有未结束预约的排班不能停诊，避免已付款患者失去后续就诊入口。
- 菜单角色选择按稳定顺序处理，避免 `Set` 迭代顺序导致角色判断不稳定。
- 业务状态异常统一返回结构化的 HTTP 409，前端不会把业务拒绝误报成“后端未启动”。
- 急症分诊没有急诊科时仍保持急症优先建议，不回退成普通内科或全科优先。

### 管理端

- 预约详情加载失败只影响对应预约行，关闭详情抽屉会清理瞬时错误状态。
- 排班历史预约数量包含已取消预约，历史排班保留原日期时可以维护允许的非身份字段；新建或改到过去日期会被拦截。
- 单条和批量时段按后端支持的 `HH:mm`、`上午`、`下午` 格式校验。
- 药师工作台纳入默认菜单保护，保留药师角色和现有菜单编辑逻辑。

### 微信小程序

- 订单、处方余额读取失败时不再按 `0.00` 误报“余额不足”，也不会继续发起余额支付。
- 订单和处方详情只接受最新请求响应，页面卸载后忽略旧响应。
- 支付成功后的刷新失败仍保留成功反馈；离页后会清理延时跳转。
- 科室列表不再固定使用 1 号科室；空目录不请求幽灵科室。
- 非法百分号参数会保留原文，避免分诊或科室页面因 `URIError` 中断。
- 移除不完整的自定义隐私回调，恢复微信默认隐私授权流程。

员工创建规则按项目约定保留：初始密码仍为 `123`，管理端展示服务端返回的初始密码，员工可以在个人信息页面自行修改。

此前的配药师删除入口继续使用与其他人员一致的现有删除逻辑；本轮没有另行设计删除功能。药师通知、角色访问和药师工作台相关场景已纳入后端专项验证。
